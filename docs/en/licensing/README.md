## Existing declaration

The root LICENSE declares MIT for its listed code and CC BY-SA 4.0 for .md documents. The authorship/license lot preserved the prior wording and added only the author identification and a catalogue note. It did not revoke permissions or impose retroactive replacement.

LICENSE contains abbreviated wording and a custom responsible-use clause. It must not be presented as a complete verbatim MIT or CC BY-SA license. Before distribution, review that wording, added restrictions, contributions and licensing authority for each component. This work has not determined which versions may previously have been distributed or to whom.

Previously granted permissions are not considered revoked by choosing another option for a future version. In particular, CC BY and CC BY-SA describe irrevocable grants under their conditions (section 2). Authorship, ownership, trademark and licensing are distinct concepts.

## Code alternatives

| Alternative | Potential purpose | Distinguishing obligation |
|---|---|---|
| MIT | Facilitate adoption, reuse and open or proprietary integration | Preserve copyright and permission notices; publication of modifications is not required |
| Apache-2.0 | Permissive adoption with express patent and notice rules | Contributor patent grant, redistribution conditions and NOTICE where applicable |
| MPL-2.0 | Share changes to covered files while allowing larger works under other licenses | File-level copyleft on distribution; retain notices and access to covered source |
| GPL-3.0-only | Keep the covered work and distributed modifications under GPL | Provide or offer corresponding source according to distribution methods; a notice alone is insufficient |
| AGPL-3.0-only | Add the network-use case for modified versions to copyleft | Section 13 requires offering corresponding source to users interacting remotely with the modified version |
| Proprietary commercial | Grant specified contractual permissions | Rights, limits, price, support and responsibilities remain undefined; inactive |
| Source-available | Expose source with bounded usage permissions | Seeing source does not mean unrestricted modification/redistribution or open-source status; inactive |

All listed open licenses allow commercial uses subject to their conditions. Charging for a copy or service does not make a license proprietary. Dual licensing is an alternative-offer strategy, not another standard license: see [DUAL-LICENSING.draft.md](DUAL-LICENSING.draft.md).

The detailed [comparison](COMPARISON.csv) supports selection; it does not replace complete texts or automatically resolve compatibility with a particular integration.

## Documentation, prompts and skill

CC BY 4.0 requires attribution and notices when sharing. CC BY-SA 4.0 adds share-alike conditions for adapted material that is shared. Both allow commercial use; neither grants patent or trademark rights. They are documentation options, not default licenses for executable software.

The existing declaration covers .md files, including skill and prompt texts. A future decision must distinguish:

- Executable code and scripts.
- Documentation, prompts and skill references.
- Schemas, configuration, YAML metadata and rubric: define these expressly because the abbreviated LICENSE enumeration does not clearly address them.
- Dependencies and other third-party materials, which retain their own terms.
- KUVEXTA GROUP's name and trademark, which are not licensed merely by offering the code.

Catalogue drafts describe possible conditions for a future product version. Whatever license applies to an explanatory document does not activate those conditions for the product.

## How to choose later

1. Define whether code, binaries, a skill, a plugin, a hosted service or a combination will be distributed, and which components each permission covers.
2. Check ownership and contributions, existing permissions, dependencies and integrations. For dual licensing, verify authority to make both offers for the specific version.
3. Choose the exact identifier and version. GPL-3.0-only is not GPL-3.0-or-later; the same applies to AGPL. Examples at the ends of texts do not imply a selection.
4. Review custom conditions, notices, patents and distribution; complete a commercial contract if that route is chosen. This catalogue does not invent prices, jurisdiction or a contracting entity.
5. Authorize a specific implementation lot: complete LICENSE, component notices, appropriate headers/metadata, communication and a new package. **Editing activada alone is not a licensing mechanism.**
